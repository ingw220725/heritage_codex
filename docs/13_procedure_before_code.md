# Procedure Before Code

## Purpose

Heritage Codex is not primarily a software-building exercise.

The scarce resource is not code.
The scarce resource is people who understand procedural responsibility.

This document exists to protect the project from a common failure mode:

> accelerating implementation before judgment, process, and precedent are real.

## The core claim

Code can implement a loop.
It cannot replace responsibility.

A working system without procedural sense will only make the wrong thing faster.

## What matters first

The project prioritizes, in this order:

1. **Procedural understanding**
2. **Small-group decision quality**
3. **Precedent quality**
4. **Implementation**

That means the first question is not:

- what framework should we use?
- how do we scale the service?
- how do we automate more?

The first questions are:

- has a threshold been crossed?
- who has authority to decide?
- is continuation still responsible?
- what must be recorded if we stop?
- what must never be silently restarted?
